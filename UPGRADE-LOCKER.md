# Locker Upgrade (v1)

Additive, non-breaking upgrade that adds a personal **My Locker** for every authenticated user.

## What was added

### New files
- `migrations/0013_locker.sql` — creates `user_favorites` and `user_locker_notes` tables
- `src/lib/locker.ts` — server functions:
  - `listMyAssignments` (surfaces existing `training_assignments` + progress + due dates + leadership notes)
  - `listFavorites` / `toggleFavorite`
  - `listLockerNotes` / `upsertLockerNote` / `deleteLockerNote` / `markReminderDone`
- `src/routes/locker.tsx` — full mobile-first Locker page with the core sections

### Modified (minimal)
- `src/components/site-header.tsx` — adds “My Locker” as the first signed-in navigation item

## Confirmed section priority (mobile-first)
1. Header / Greeting
2. Due & Assigned Courses (with due date, leadership note, progress, Continue)
3. Continue Learning / Next Up
4. Personal Notes & Reminders
5. Favorites
6. Progress Snapshot
7. Quick Actions

## How to apply safely
1. Copy the new/changed files into your repo (or merge this branch).
2. Run the new migration as part of your normal release process:
   ```bash
   MIGRATIONS_REQUIRED=true npm run release
   # or
   npm run db:migrate
   ```
3. Deploy. Existing Team assignment flow, progress, quizzes, auth, and all prior features remain unchanged.
4. Managers continue setting due dates + notes on `/team`. Those now appear in each learner’s Locker.

## Notes
- The Locker reuses the existing `training_assignments` table (already had `due_on` + `note`).
- No existing tables or critical paths were altered.
- Route is protected by the standard AuthGate.
- After deploy, Specialists will see “My Locker” in the header.

Iterate based on real Specialist feedback after shipping v1.

## Integration review (applied before merge)

The upgrade as submitted **did not compile** — `tsc --noEmit` reported 11 errors,
most of which were runtime bugs rather than type nits. All were fixed during
integration; the notes below are the record.

### Bugs fixed

| Where | Problem | Fix |
|---|---|---|
| `lib/locker.ts` | `next?.lessonTitle` — `ContinueTarget` exposes `title`, so this was always `undefined` and **Next Up rendered no lesson name** | read `next?.title` |
| `routes/locker.tsx` ×3 | `upsertLockerNote({ body })`, `deleteLockerNote({ id })`, `markReminderDone({ id })` omitted the `{ data: … }` envelope every server fn requires — **every note write would have failed** | wrapped in `{ data: … }` |
| `routes/locker.tsx` | `user?.name` — `AppUser` exposes `displayName`, so the greeting always fell through to "Hello, there." | `user?.displayName` |
| `routes/locker.tsx` ×2 | `to="/training/$track_/$lesson"` is not a real route — **both Continue buttons were broken** | `to="/training/$track/$lesson"` |
| `routes/locker.tsx` | `<Button variant="default">` — no such variant (`primary\|invert\|outline\|ghost\|brass`) | `variant="primary"` |
| `routeTree.gen.ts` | stale; did not contain `/locker` | regenerated by the build |
| `routes/locker.tsx` | unused `BookOpen` / `Pin` imports | removed |

### Improvements added

- **Due dates now compare in `America/Chicago`.** `new Date(dueOn + "T23:59:59")`
  parsed in the *server's* zone — UTC on Vercel — so for the first hours of each
  Central day an assignment due today was reported **overdue**. This is the same
  defect already fixed in `digest.ts`; the Locker and the weekly digest now agree.
- **Reminders are a toggle.** `done_at` could be set but never cleared, so a
  mis-tap was permanent. A done note is also now visibly struck through and
  labelled, where before it looked identical to a plain note.
- **Input validation.** Note bodies capped at 2000 characters (matching
  "Ask the trainer"); `reminderOn` validated as `YYYY-MM-DD` before it reaches a
  Postgres `date` column; `targetType` validated against the CHECK constraint.
  Each previously surfaced as a raw driver error and a 500.
- **`toggleFavorite` no longer 500s on a double-tap.** Select-then-insert raced
  the unique index; now `on conflict do nothing`.
- **No more silent no-ops.** Editing, deleting or completing a note that does not
  exist (or belongs to someone else) reported success. All three now use
  `returning id` and raise a real message.
- **Bounded queries** (`limit 200`/`500`), consistent with the rest of the
  codebase, and a **cancellation guard** so a late reload cannot set state after
  unmount.

### Verified

Signed in on mobile (390px) and desktop: Locker renders, greeting resolves to the
real name, note create/delete round-trips, header nav present, all 7 sections
wired, **0 console errors**, `tsc` 0, `eslint` 0, 51/51 tests, build exit 0.

### Not changed

Nothing existing was altered beyond the single additive nav line in
`site-header.tsx`. No table, route, or prior feature was touched — the security
headers, CSP, catalog redaction, provisioning flow and lesson links are all intact.
